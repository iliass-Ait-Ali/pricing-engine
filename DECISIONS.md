# Decisions

Every meaningful choice, the alternatives considered, and why. Dated by the
phase in which the decision was taken (2026-08-18 build).

| # | Decision | Alternatives | Why |
| --- | --- | --- | --- |
| 1 | **Dataset**: Dominick's Cereals (Kilts Center), official URLs only | Kaggle mirrors; synthetic data | Real, documented store-level scanner data with prices, promotions and margins. Mirrors have unknown provenance; synthetic data cannot support a pricing portfolio claim. Synthetic fixtures are used only for unit tests. |
| 2 | **Unit of analysis**: `upc x store x week` | UPC x week (pooled stores); UPC x chain | Dominick's priced by store zone, and the observed cross-store price spread (median 13.6% per UPC) confirms store is a real pricing dimension. |
| 3 | **Effective unit price** = `price / qty` | Use `price` directly | `price` is a bundle price; 0.105% of rows have `qty > 1`, which would be mispriced by 2-4x. |
| 4 | **Cost naming**: `estimated_unit_aac`, never `true_unit_cost` | Generic "cost" | `profit` is a margin on Average Acquisition Cost, an accounting measure that can differ from replacement cost. |
| 5 | **Validity rule**: keep `ok = 1` only | Keep everything; keep with a flag | The manual defines `ok = 0` as suspect/trash (141,285 rows, 2.14%). Count is documented rather than hidden. |
| 6 | **Zero-price rows excluded** (1,753,521 rows, 26.56%) | Impute a price; keep with NaN price | No unit price can be derived; these are weeks with no priced offer. Documented as a rule, not an ad-hoc outlier cut. |
| 7 | **No arbitrary outlier trimming** | Winsorise price/units | Extremes are reported and flagged (`margin_implausible_flag` etc.) and handled downstream by the extrapolation guardrail instead of being deleted to make plots look tidy. |
| 8 | **Week decoding**: `1989-09-14 + (week-1)*7` | Leave `week` as an integer feature | The manual anchors week 1; decoding gives real calendar seasonality and yields the documented 1989-09-14 .. 1997-05-01 range as a check. |
| 9 | **Promotion naming**: `recorded_promotion_flag/type`, `NONE_RECORDED` | `is_promo` / `no_promo` | Coding is incomplete; a missing code does not prove no promotion. Undocumented codes `G` and `L` are surfaced as `UNKNOWN_CODE` rather than silently mapped. |
| 10 | **Target**: `move` (units) | Revenue; gross profit; log units | Revenue and profit are functions of the target - using them is leakage. Money is derived after prediction, which is also what makes the counterfactual coherent. |
| 11 | **Split**: chronological by week (70/15/15) | Random split; group k-fold | Time-indexed autocorrelated panel; a random split leaks the future of each series. |
| 12 | **Decision-time cost**: lagged, forward-filled AAC | Contemporaneous AAC | The current week's accounting margin is an outcome. If no prior cost exists the optimizer returns `COST_UNAVAILABLE` rather than inventing one. |
| 13 | **Promotion flag treated as known at decision time** | Drop it entirely | Promotion calendars are agreed in advance, so it is realistic - but it is an assumption, stated in the leakage audit, with error reported separately by promotion state. |
| 14 | **Models compared**: 4 naive baselines, ridge log-log, HGB Poisson | Add LightGBM/XGBoost/CatBoost | One strong boosted implementation is enough; installing three for appearance adds no information. Poisson loss suits weekly counts and guarantees non-negative predictions. |
| 15 | **Selected model**: ridge log-log (valid WAPE 0.4135 vs 0.4226) | Always pick the boosted model | Selection rule fixed in advance: lowest validation WAPE among price-aware models. The linear model also exposes an interpretable price response. |
| 16 | **`time_index` excluded from the linear model only** | Keep it everywhere; drop it everywhere | A standardised unbounded trend extrapolated into the future window exploded after exponentiation (observed WAPE 27.9 before the fix). Trees saturate, so the boosted model keeps it. |
| 17 | **Prediction cap at 5x max training demand** | No cap; clip at a fixed number | Exponentiating a linear prediction can explode on extreme inputs. The cap is recorded in the artifact and documented, not silent. |
| 18 | **UPC not used as a raw categorical** | One-hot 489 UPCs; native categorical | HistGradientBoosting caps categorical cardinality at 255. Instead a smoothed `upc_demand_prior` learned on training rows only, plus relative-price features that carry the price response. |
| 19 | **Grid optimizer, not a continuous solver** | scipy.optimize | The demand model may be a step function; a grid makes constraints, reason codes and analytical tests exact, and is vectorised in one batched prediction. |
| 20 | **Primary objective**: expected gross profit; revenue supported | Revenue only | Profit is the business objective; revenue is offered because it is sometimes the mandate (share/volume goals). Both use the same predicted demand. |
| 21 | **Cost held fixed across the candidate grid** | Reuse the historical margin percentage | Reusing the margin % mechanically manufactures profit at any price. Enforced by test. |
| 22 | **Extrapolation guardrail**: observed support x (1 +/- tolerance), intersected with max change | A universal +/-X% rule | Support is series-specific; a single magic number would be arbitrary. Tolerance and cap are configured, not hardcoded. |
| 23 | **Materiality threshold** (1% standard) | Always take the argmax | With weekly WAPE ~0.46, sub-1% estimated gains are noise. Produces the `KEEP_CURRENT_PRICE` outcome that a credible engine must have. |
| 24 | **Risk layer is heuristic and labelled as such** | Call it confidence; fit prediction intervals | It is a transparent rule over history, price variation and extrapolation distance. Calling an uncalibrated score "confidence" would be dishonest. |
| 25 | **Three DEMO policy profiles** | One fixed policy | Makes the sensitivity of recommendations to policy explicit; labelled as demo settings, not best practice. |
| 26 | **Backtest reports model-estimated policy economics with a circularity warning** | Report it as achieved uplift | The same model chooses and scores; the only verifiable part is demand accuracy through time, which is reported separately. |
| 27 | **Raw and processed data git-ignored; CI never downloads them** | Commit a sample | Academic-use licence. A test asserts the ignore rules. |
| 28 | **Recommendation log in CSV with lifecycle states** | SQLite; no log | CSV is enough for a demo and diffable; the lifecycle (GENERATED -> ... -> PUBLISHED) documents the human-in-the-loop design. |
| 29 | **Plotly (not `st.bar_chart`) in the dashboard** | Altair-backed helpers | Altair 5.4 does not import on Python 3.13 in this environment; Plotly keeps the app runnable and the choice is commented in code. |
| 30 | **Package installed from `src/` layout, editable** | Flat layout with `sys.path` hacks | Keeps imports identical for scripts, tests, API and dashboard. |

## Phase L - pricing-science hardening (2026-08-18)

| # | Decision | Alternatives | Why |
| --- | --- | --- | --- |
| 31 | **Separate forecasting from price response**: Q(p) = Q_hat(p0) * (p/p0) ** epsilon | keep using the ML model's own price response; fit a structural demand system | The selected model's implied elasticity (-3.10) is far steeper than the controlled estimate (-1.91/-2.42). The hybrid keeps the forecaster's contextual skill and replaces only the part it is not qualified to answer. At p = p0 it reproduces the ML prediction exactly, so nothing is lost at the observed price. |
| 32 | **Default price-response method: `shrunk`** (per-UPC empirical-Bayes elasticity) | pooled only; raw per-UPC; native ML | Raw per-UPC coefficients are noisy (100 products too thin, 24 wrong-signed); a single pooled number ignores real heterogeneity (tau^2 = 1.10). Shrinkage is the defensible middle, and each product's weight is recorded. |
| 33 | **Keep the native ML response as `--method ml`** | delete it | It is the honest benchmark and the reason the change was made. reports/08 compares all three methods on identical contexts. |
| 34 | **Elasticities estimated on training weeks only (2-257)** | full sample | Fitting on validation/test weeks would leak those outcomes into the recommendations evaluated there. The script aborts if input rows exceed the window, and the window is stored in the table metadata. |
| 35 | **Reject wrong-signed and imprecise product estimates before shrinking** | shrink everything | A positive coefficient is evidence of endogeneity, not of upward-sloping demand; shrinking it would smuggle that contamination into the blend. |
| 36 | **Risk scale inverted so HIGH means risky**, with bands stricter than the eligibility screen | keep HIGH = "high confidence" | The old naming read backwards - a "HIGH" label sat on actionable recommendations. Eligibility answers "can this be modelled at all"; risk answers "should we act on it". |
| 37 | **Three decision states**: RECOMMEND_CHANGE / KEEP_CURRENT / REVIEW_REQUIRED, plus an `actionable` flag | binary change/keep | A HIGH-risk context can still deserve a human's attention; silently keeping the price throws that information away. |
| 38 | **HIGH risk is never auto-actionable under default profiles** (`high_risk_action`: review_required for standard, keep_current for conservative) | rely on constraints alone | Constraints bound the size of a mistake, not its likelihood. Only the explicitly labelled DEMO `aggressive` profile may override. |
| 39 | **Uplift renamed `model_internal_estimated_*`** across code, API, dashboard and reports | keep "model-estimated" | The same fitted response proposes and scores the price; "internal" puts that circularity in the field name itself, where it cannot be dropped in a slide. |
| 40 | **Zero-price rule kept, but evidenced** | impute prices; keep the rows | Only 677 of 1.85 M zero-price rows recorded sales, and 73.4% are leading/trailing runs. Imputing would fabricate the optimised variable. The resulting selection tilt is documented instead. |
| 41 | **Reference price is stamped explicitly, and a missing one raises** | silently fall back to the row's current price | During candidate scoring the row's price IS the candidate, so a silent fallback would make the elasticity term vanish and quietly return baseline demand. A loud error is safer than a silent no-op. |
| 42 | **Backtest accuracy is scored with the baseline forecaster, policies with the pricing model** | score everything with the hybrid | WAPE measures forecasting at observed prices, which is the baseline model's job; the price-response layer only matters for counterfactuals. |

## Phase M - final scientific audit (2026-08-18)

| # | Decision | Alternatives | Why |
| --- | --- | --- | --- |
| 43 | **Report the constraint dominance as the headline architectural fact** | present the project as "ML pricing" and leave the attribution in an appendix | The attribution over all 13,964 week-399 contexts says 2.9% of final recommendations come from an interior optimum of the estimated price response and 57.1% sit on a guardrail corner. A rule with no demand model matches the engine within one 5-cent grid step 82.5% of the time. Hiding that would make every other claim suspect; leading with it makes the project a demonstration of auditing, which is the more valuable skill to show. `reports/11`, `reports/12`, `reports/13`. |
| 44 | **Per-UPC standard errors are panel-robust (max of store- and week-clustered), not HC1** | keep HC1; two-way cluster inside each product | HC1 assumes no within-store persistence and no category-wide weekly shocks, both of which obviously exist. Clustering inflates the per-UPC standard error by a median factor of 3.8. Two-way clustering inside a single product has too few clusters to be stable, so the conservative max of the two one-way estimators is used; two-way IS used at the pooled level, where it is stable. `reports/15`. |
| 45 | **tau^2 estimated by REML, around the prior mean the shrinkage actually targets** | keep the method-of-moments estimator around the sample mean | The moment estimator truncates at zero more often, and measuring dispersion around the sample mean while shrinking toward the pooled estimate is internally inconsistent. Empirically the two centres are close here (-1.93 vs -2.03), so this fix mattered far less than the standard-error fix. `reports/14`. |
| 46 | **Mean shrinkage weight moved 0.954 -> 0.780 and the old figure was removed from every document** | keep the published number | The 0.95 was an artifact of understated standard errors, which inflate the weight from both directions at once. The corrected 0.78 is still high, and that part is genuine: tau ~ 0.88 against a median robust standard error of 0.39. |
| 47 | **`recommended_price` split into `proposed_candidate_price` and `final_recommended_price`** | keep one field plus the `actionable` flag | A single field holding the proposal meant any consumer that forgot to read `actionable` would display a price the policy had refused to authorise. `price_change_pct` now refers to the final price and is 0 for non-actionable rows, and `realisable_profit_uplift_pct` is forced to 0 so a non-actionable proposal can never be summed into a portfolio figure. `reports/19`. |
| 48 | **`build_bounds` reports constraints binding at the final interval, not every constraint that tightened a running bound** | keep the sequential log | The old logic appended `PRICE_CHANGE_LIMIT` whenever the change window beat the absolute floor, even when the extrapolation guardrail later superseded it, over-reporting how often the cap binds. Found while validating the attribution replica against the real optimizer. |
| 49 | **Audit uses an exact replica of the optimizer, pinned by tests, rather than the optimizer itself** | run `optimize_price` 11x per context | The replica is ~450x faster, which is what makes leave-one-out attribution over 13,964 contexts and five policy layers feasible at all. It is only trusted because `tests/test_attribution.py` asserts identical decision state, final price and reason codes across 60 parameter combinations, and it was checked against 400 real contexts with zero mismatches. |
| 50 | **`shrunk` retained as the default price-response method, on out-of-time evidence** | switch to `pooled`; switch to native ML | On 154,899 unseen price-change episodes in weeks 258-399, `shrunk` has the lowest WAPE in every split, including the non-promotion split that matters most (0.560 vs 0.588 native ML, 0.594 pooled, 0.715 for a no-price-response null). The fallback chain is unchanged and is itself the conditional strategy: usable product estimate -> shrunk; otherwise -> pooled; insufficient history or price variation -> KEEP_CURRENT. `reports/16`. |
| 51 | **"No forecast skill is lost" removed from every document** | keep the shorthand | The equality `Q_hybrid(p0) = Q_ML(p0)` holds at the reference price only; away from it the curve is the elasticity model's, and its accuracy is a separate empirical question. Replaced with the precise statement and pinned by parametrised regression tests over five elasticities and three price levels. |
| 52 | **`scripts/audit_claims.py --strict` added as an enforceable check** | rely on review | Wording drifts back. The scanner classifies every occurrence of ten watched phrases, recognises disclaimers as disclaimers, and fails the build if an UNSUPPORTED claim reappears. `reports/20`. |

## Phase N - engineering closure and v1.0 freeze (2026-08-19)

No scientific method changed in this phase. Every decision below is about
reproducibility, honesty of wording, or engineering hygiene.

| # | Decision | Alternatives | Why |
| --- | --- | --- | --- |
| 53 | **The executive summary states both scale illustrations in their units** ("a 1% *relative* increase in the gross-profit total ≈ $0.4 M" **and** "a +1 *percentage point* gross-margin rate on $262.0 M of revenue ≈ $2.6 M") | keep the single "1% improvement in realised gross margin ≈ $400,000" sentence | The original wording mixed a relative change in gross *profit* with a percentage-point change in the margin *rate*. The two differ by a factor of 6.5 on this panel, so the sentence was ambiguous in exactly the direction that flatters the project. Both are now labelled arithmetic illustrations of category scale, explicitly not estimated uplift. |
| 54 | **The batch path is vectorised through the existing `simulate_many`, behind an equivalence contract** | leave the per-context loop; rewrite the optimizer around a batch-first API | `optimize_price` was split into `_prepare_context` / `_finalise_context`, and *both* entry points run the same two stages - so pricing logic, guardrails, elasticity selection and risk policy cannot diverge between them by construction. The batch entry point only changes how many rows reach the model at once: contexts are grouped by candidate-grid width and scored through `simulate_many`. Measured on 3,000 real contexts: 122.0 s → 2.4 s, with **bit-identical** output on every compared field (`artifacts/metrics/batch_performance.json`). |
| 55 | **Equivalence is asserted field by field, exactly for discrete fields** | compare final prices only; compare summary statistics | A batch path that agreed on price but disagreed on a reason code or a risk level would be a silent audit-trail defect. `tests/test_batch_equivalence.py` compares proposed price, final price, decision state, actionable, elasticity source, risk level, reason codes, risk notes, predicted units, revenue, gross profit, uplift and the diagnostics dictionary, for three policy profiles and both objectives. |
| 56 | **The audit scripts keep the per-context path** | switch every audit to the batch path too | The Phase M audits already run through a pinned optimizer replica and produce the frozen scientific artifacts. Changing their execution path at freeze time would have risked perturbing those artifacts for no benefit. |
| 57 | **README headline metrics are generated into a delimited block** | keep hand-copied tables; regenerate the whole README | Documentation drift was a real, repeatedly observed defect in this project. `scripts/update_readme_metrics.py` writes only the region between `<!-- BEGIN/END GENERATED METRICS -->`, from the artifacts that own each number; prose is never touched. `tests/test_readme_metrics.py` fails when the block is stale, and separately when the published test count differs from what pytest collects in that very run. |
| 58 | **The model-internal profit uplift is deliberately excluded from the generated headline block** | include it - it is the most impressive number | It is a self-scored offline simulation, not business impact. It remains in the report and in `reports/07`, always labelled; it is not a headline metric. A test asserts that any uplift line in the block carries the "model-internal" qualifier. |
| 59 | **A cross-document numeric audit compares every hand-authored statement with its owning artifact** | rely on the claim audit and review | The claim audit classifies *phrases*; it cannot see that "87.3%" should be "86.7%". `scripts/audit_metric_consistency.py` anchors on the metric name, so it compares like with like, and it deliberately does **not** flag lines that record a correction ("0.954 → 0.780") - superseded values are history, and this project does not delete history. 212 statements checked, 0 mismatches. |
| 60 | **The audit scans hand-authored documents only** | scan every Markdown file | `reports/01`-`reports/20` are rewritten from the artifacts by their own scripts on every run, so they cannot drift; including them would only add noise. The drift registers and the claim audit are excluded for the same reason in reverse: their subject matter *is* other documents' wrong numbers. |
| 61 | **The DOCX cover metadata and the PDF are generated, and the page count is read back from Word** | keep typing the cover facts; export the PDF by hand | The cover page previously asserted a test count and a WAPE by hand - the same defect class as the README. `scripts/export_report_pdf.py` drives Word to repaginate, update the table-of-contents field and export, then records pages, word count and heading counts in `artifacts/metrics/report_build.json`. The Markdown remains the only source of truth; the DOCX and PDF are never edited. |
| 62 | **Version pinned to 1.0.0 in one place, and read from there** | keep the version in `pyproject.toml`, `__init__.py` and the FastAPI app separately | `src/pricing_engine/__init__.py` holds `__version__`; the API imports it. Three hand-maintained copies is how a service ends up reporting a version it is not running. |
| 63 | **One honest initial commit rather than a reconstructed history** | fabricate per-phase commits with back-dated messages | The repository had no commits when this phase began. Inventing a plausible sequence of historical commits would misrepresent when the work happened - the same category of dishonesty this project spends twenty reports avoiding. The work is instead split into coherent commits made now, and the phase history lives in `ROADMAP.md` and `DECISIONS.md`, where it is documented rather than simulated. |
